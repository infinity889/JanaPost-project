# Jana Address — Автономная система разбора и гео-обогащения адресов доставки (Jana Post Hackathon)

**Jana Address** — гибридная система разбора и гео-обогащения неструктурированных казахстанских адресов доставки (`raw_address`), разработанная в строгом соответствии с ТЗ хакатона **Jana Post**.

Система преобразует произвольную адресную строку (с опечатками, слитными конструкциями, двуязычными дублями RU/KZ, перестановками и телефонными пометками) в **12 структурированных полей** и восстанавливает пропущенные административные уровни (`district`, `street_type`, `city`, `province`) по локальной базе **КАТО + OpenStreetMap (`kaz_geo.sqlite`)** полностью **офлайн (без интернета)**.

---

## 1. Запуск одной командой (`Docker Compose`)

Вся система (FastAPI Backend + SQLite гео-справочник + React/Nginx Web UI) запускается одной командой без внешних сетевых запросов:

```bash
docker compose up --build
```

После старта сервисы доступны по адресам:
- **Веб-интерфейс оператора (UI):** `http://localhost:8080`
- **REST API (Swagger / OpenAPI):** `http://localhost:8000/docs`
- **Пакетный эндпоинт проверки:** `POST http://localhost:8000/api/parse` (также проксируется через `http://localhost:8080/api/parse` и `POST /parse`)
- **Проверка здоровья и статистики БД:** `GET http://localhost:8000/api/health`

Время старта контейнеров: **< 5 секунд** (лимит ТЗ — до 3 минут).  
Скорость пакетного разбора 1000 записей на CPU: **~0.05 – 0.25 секунды** (лимит ТЗ — до 5 минут).

## 2. Локальный запуск и проверка точности (без Docker)

### Сборка гео-справочника и запуск стресс-теста (`offline_check.sh`)
```bash
bash scripts/offline_check.sh
```
Скрипт выполняет 4 шага:
1. Собирает локальную базу `backend/data/kaz_geo.sqlite` (`scripts/build_gazetteer.py`) и выводит отчёт по покрытию (`scripts/gazetteer_report.py`).
2. Прогоняет конвейер парсера на валидационной выборке (`data/val_input.json`) и выполняет бенчмарк на **1000 записей**.
3. Считает точность по официальной формуле ТЗ (`evaluate.py`):
   $$\text{Score} = 0.60 \times \text{Address} + 0.25 \times \text{Details} + 0.15 \times \text{Reference}_{\text{in\_string}}$$
   а также проверяет инварианты ТЗ и полноту гео-обогащения (`district`, `street_type`, `landmark` для 30% оценки на защите).
4. Проверяет продакшн-сборку фронтенда (`npm run build`).

### Запуск Backend вручную
```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### Запуск Frontend вручную
```bash
cd frontend
npm install
npm run dev
```

## 3. Архитектура 6-шагового конвейера (`backend/app/parser/`)

Каждая входная запись `{"id": "...", "raw_address": "..."}` проходит через детерминированный **Span-preserving** конвейер без использования предзаготовленных ответов по `id` или полному совпадению строки:

1. **Токенизация с сохранением символьных координат (`preprocessor.py`):**
   - Безопасное разделение слитных конструкций только для целевых якорей: `66квартал` $\rightarrow$ `66 квартал`, `11дом` $\rightarrow$ `11 дом`, `4подьезд` $\rightarrow$ `4 подьезд`, `9этаж` $\rightarrow$ `9 этаж`, `69квартира` $\rightarrow$ `69 квартира`, `Назарбаева8` $\rightarrow$ `Назарбаева 8`.
   - Защита валидных номеров с литерами (`12А`, `3а`, `19а`, `55/6`) от ложного разбиения.
2. **Разбор «Шапки» (`province`, `city`, явный `district`):**
   - Схлопывание двуязычных дублей через `/` (`город Алматы/Алматы қаласы` $\rightarrow$ `Алматы`, `Область Актюбинская/Ақтөбе облысы` $\rightarrow$ `Актюбинская область`).
   - Приведение `province` к строгому прямому порядку со словом «область» (`«Актюбинская область»`, `«Карагандинская область»`) и без слова «область» для городов республиканского значения (`«Алматы»`, `«Астана»`, `«Шымкент»`).
   - Очистка `city` и `district` от служебных слов (`г.`, `пос.`, `район`, `ауданы`).
3. **Разбор «Хвоста» (`apartment`, `entrance`, `floor` — 25% авто-метрики):**
   - Явные якоря (`кв`, `пәтер`, `подъезд`, `подьезд`, `этаж`, `қабат`).
   - Контекстное правило «голого хвоста» после номера дома (`Улица Курильская, 9, 2` $\rightarrow$ `house="9"`, `apartment="2"`).
4. **Извлечение ориентиров и примечаний (`landmark`):**
   - Распознавание ЖК (`ЖК ...`), бизнес-центров (`БЦ ...`), торговых центров, углов улиц (`уг. ...`), курьерских примечаний и телефонов (`позвонить заранее 87071234567`) строго как подстроки `raw_address`.
   - Защита неразборчивого мусора (`asdfgh 12345 ???`) — возвращаются `null` во всех полях и низкий `confidence`.
5. **Разбор ядра адреса и развилка «Микрорайон vs Улица» (`living_area`, `street_type`, `street_name`, `house`):**
   - **Сценарий А (микрорайон + отдельная улица):** `пос. Боралдай, мкр Водник, ул Абая 1/2` $\rightarrow$ `living_area="Водник"`, `street_type="улица"`, `street_name="Абая"`, `house="1/2"`.
   - **Сценарий Б (адресация по микрорайону/кварталу без улицы):** `Мкр Аксай 3а, 59` $\rightarrow$ `living_area=null`, `street_type="микрорайон"`, `street_name="Аксай 3а"`, `house="59"`.
   - **Строгая подстрочность:** `street_name` возвращается в точности как в `raw_address` (`«казибек би»` остаётся `«казибек би»` без исправления регистра и опечаток).
6. **Локальное гео-обогащение (`gazetteer.py` + `kaz_geo.sqlite`):**
   - Поиск по таблицам `settlements`, `urban_districts`, `streets`, `buildings` с поддержкой нечёткого сопоставления (`RapidFuzz`).
   - Дозаполнение `district`, `street_type`, `city`, `province` **только если они `null`** после парсинга текста (данные из строки никогда не перезаписываются справочником).

## 4. Спецификация REST API

### `POST /api/parse` (также `POST /parse`)
Принимает JSON-массив входных записей (или объект `{"records": [...]}`) и возвращает JSON-массив разобранных объектов строго той же длины и с теми же `id` и `raw_address`.

**Пример запроса:**
```bash
curl -X POST http://localhost:8000/api/parse \
  -H "Content-Type: application/json" \
  -d '[
    {"id": "rec_00419", "raw_address": "Алматы, казибек би 117/1, кв 5"},
    {"id": "rec_00422", "raw_address": "Караганда 66квартал 12дом 3кв"}
  ]'
```

**Пример ответа:**
```json
[
  {
    "id": "rec_00419",
    "raw_address": "Алматы, казибек би 117/1, кв 5",
    "province": "Алматы",
    "city": "Алматы",
    "district": "Алмалинский",
    "living_area": null,
    "street_type": "улица",
    "street_name": "казибек би",
    "house": "117/1",
    "apartment": "5",
    "entrance": null,
    "floor": null,
    "landmark": null,
    "confidence": 0.92
  },
  {
    "id": "rec_00422",
    "raw_address": "Караганда 66квартал 12дом 3кв",
    "province": "Карагандинская область",
    "city": "Караганда",
    "district": "Казыбек би",
    "living_area": null,
    "street_type": "квартал",
    "street_name": "66",
    "house": "12",
    "apartment": "3",
    "entrance": null,
    "floor": null,
    "landmark": null,
    "confidence": 0.94
  }
]
```

## 5. Структура репозитория

```text
JanaPost-project/
├── backend/
│   ├── Dockerfile               # Образ FastAPI + SQLite (офлайн)
│   ├── requirements.txt         # Зависимости Python (FastAPI, RapidFuzz, Pydantic)
│   ├── data/
│   │   └── kaz_geo.sqlite       # Локальная гео-база КАТО 2026 + OSM РК (4.1 МБ: 2080 нас. пунктов, 16597 улиц/мкр)
│   └── app/
│       ├── main.py              # REST API (/api/parse, /parse, /api/parse-file, /api/health)
│       ├── schemas.py           # Строгие Pydantic-модели по ТЗ
│       └── parser/
│           ├── preprocessor.py  # Span-токенизация и разделение слитных конструкций
│           ├── pipeline.py      # 6-шаговый парсер адресов (RU + KZ маркеры, перекрёстки, мкр)
│           └── gazetteer.py     # Поиск и гео-обогащение по SQLite + RapidFuzz + диапазоны домов
├── frontend/
│   ├── Dockerfile               # Multi-stage сборка React + Nginx
│   ├── nginx.conf               # Раздача UI и проксирование /api на backend
│   └── src/                     # Веб-интерфейс оператора (таблица, фильтр confidence, инспектор)
├── scripts/
│   ├── fetch_kato_and_osm.py    # Выгрузка КАТО 2026 (НК РК 11-2021) + улиц 20 областных центров из OSM
│   ├── build_gazetteer.py       # Сборка kaz_geo.sqlite из справочников КАТО 2026 + OSM
│   ├── gazetteer_report.py      # Отчёт по покрытию регионов, районов и улиц
│   ├── run_eval.py              # HTTP-проверка API, прогон валидации и бенчмарк 1000 записей
│   └── offline_check.sh         # Полный автотест проекта одной командой
├── data/
│   ├── kato_osm_cache.json      # Кэш КАТО 2026 и OSM по всем 20 регионам РК (4.7 МБ)
│   ├── val_input.json           # Валидационный входной батч (32 записи, все ловушки ТЗ)
│   └── val_ground_truth.json    # Эталонная разметка для самопроверки
├── evaluate.py                  # Скрипт расчёта метрики ТЗ (60% / 25% / 15% + инварианты)
└── docker-compose.yml           # Запуск всей системы одной командой
```
